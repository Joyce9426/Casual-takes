# 隨手場記m・場次人員管理 PWA（會員版）

> 這是從「隨手場記」獨立出來的新專案，程式碼、部署（Worker/D1）、App 識別
> 都跟原本的單機版分開，互不影響。現在需要登入才能使用，不同使用者登入後
> 只看得到自己的資料，admin 則可以看所有人的資料。下面 v55 以前的更新紀錄
> 是從原專案繼承過來的既有功能歷史，供參考。

**部署前必做**：把 `js/config.js` 裡的 `API_BASE_URL` 改成你自己
`relay/` 這個 Worker 部署完成後拿到的網址，否則 App 連不上後端、無法登入。
帳號要先由 admin 建立（見 `relay/README.md` 的「帳號系統設定」），這個
App 本身沒有自助註冊功能。

需要登入才能使用，資料存在 Cloudflare D1（伺服器為主），本機 IndexedDB
只是加快讀取速度的快取，登入後會自動跟伺服器同步（不需要手動開關）。

## v55 更新內容
- 修正「場次的依付款方式加總，誤把已請假的季打人員金額也算進去」的問題。原因是季打人員如果曾經以單場繳費方式付過款（記錄了繳費方式），之後才被改成請假，這筆繳費方式紀錄沒有被清掉，導致統計時被重複算進去。現在改成兩處：計算邏輯本身會排除請假的季打（不管有沒有殘留的繳費方式紀錄），另外把出席狀態改成「請假」的當下，也會自動清掉這筆已經記錄的繳費方式，避免類似的殘留資料再度發生

## v54 更新內容
- 修正季打退費詳情訊息裡「只有冷氣區塊、沒有請假區塊」時會多出一條分隔線的問題。原因是頂部（總退費金額下方）的分隔線原本是固定顯示的，冷氣區塊自己前面又會加一條，兩條線正好連在一起變成重複；現在改成頂部分隔線只在「後面確實有內容」時才顯示，冷氣區塊自己的分隔線也只在「前面確實有請假區塊」時才加，各種組合（只有請假、只有冷氣、兩者都有、兩者都沒有）都驗證過分隔線數量正確

## v53 更新內容
- **真正找到並修正了退費詳情訊息推送失敗的原因**：`buildRefundDetailFlexMessage` 裡有幾個地方用了 `alignItems: 'baseline'`，但 LINE Flex Message 規格其實只接受 `flex-start`／`flex-end`／`center` 這三種值，不支援 `baseline`。這個問題只有在真的送出訊息時才會被 LINE 的 API 拒絕（回傳 400 錯誤），本機測試沒辦法透過畫面確認格式對不對，所以一直沒被抓到。已經全部改成 `center`，並新增一項會遞迴檢查整個訊息結構的測試，往後任何地方誤用了 LINE 不支援的屬性值都會在測試階段就被抓出來，不用等到真的發送失敗才發現

## v52 更新內容
- 儲存退費詳情的檢查邏輯加強：原本只看 HTTP 狀態碼是不是 200，現在會**進一步確認 Worker 回傳的「實際寫入筆數」跟送出的筆數一致**——如果 Worker 靜默跳過了某些資料（例如格式不符），原本會誤判成功，現在會正確顯示「儲存失敗」
- 瀏覽器主控台（DevTools Console）新增除錯訊息，會印出準備儲存的 memberId 清單，以及 Worker 實際回傳的內容，方便排查問題卡在哪一步

## v51 更新內容
- 修正「發送季打結算總表後，點擊 postback 查不到退費詳情」的問題。真正原因是儲存退費詳情這個步驟被設計成「不等待的背景動作」——送出成功的提示一跳出來，使用者很容易立刻把 App 切到背景或關掉，這時候手機瀏覽器常常會直接終止還在背景執行中的網路請求，導致資料根本沒送到 Worker。現在改成**等儲存也完成後，才會關閉視窗、顯示「已發送」**，確保兩個步驟一定會一起完成

## v50 更新內容

- 這一步驟改用你已經在用的 LINE 通關密語（X-Api-Key）驗證，**不需要另外設定或啟用雲端同步**——如果你的群組訊息本來就能正常發送，這個新功能不用多做任何設定就會一起生效
- 需要搭配同步更新的 Worker（`sunday-roster-line-relay-v3-refund-postback.zip`，這次也一併修正了它裡面的驗證方式）

## 如何使用（本機開啟）

因為瀏覽器安全限制，Service Worker（離線快取）與 IndexedDB 在 `file://` 直接開啟時可能無法正常運作，**建議用一個簡單的本機伺服器來開啟**：

### 方法一：使用 Python（大多數電腦都有）
```bash
cd 這個資料夾
python3 -m http.server 8080
```
然後用瀏覽器打開 `http://localhost:8080`

### 方法二：使用 Node.js
```bash
cd 這個資料夾
npx serve .
```

打開後，手機瀏覽器可以用「加入主畫面」／桌面瀏覽器網址列的「安裝」圖示，把它安裝成一個 App。

## 如何部署到網路上（讓手機直接連網址使用）

這是純前端靜態網站，沒有後端，可以直接放到任何靜態網站託管服務，例如：
- **GitHub Pages**：把這個資料夾內容 push 到一個 repo，開啟 GitHub Pages 指向該分支即可。
- **Cloudflare Pages / Netlify / Vercel**：把資料夾拖拉上傳即可部署，幾分鐘內拿到一個網址。

部署後用手機瀏覽器打開該網址，一樣可以「加入主畫面」安裝成 App。

## 資料備份

所有資料只存在單一瀏覽器、單一裝置裡。**強烈建議定期到「設定」頁面按「匯出 JSON 備份」**，把備份檔存到雲端硬碟等地方。若要更換裝置或清除瀏覽器資料前，也請先匯出備份，之後可以用「匯入 JSON 備份」還原。
